# 应物音形汉字键入方案

> 原名：应物音形衡码输入法
> 方案版本 0.4.1　｜　本文所有数字均取自仓库现值，重出命令见 §5.8

一套汉字键入方案：**全拼承担读音，结构与部件承担字形**，二者按固定次序拼接成一枚编码。

```text
全拼  →  加结构码  →  加一个部件码  →  加第二个部件码  →  加第三个部件码
qing  →  qingz     →  qingzs        →  qingzsq        →  qingzsqr       （清）
```

每一级都是可用的编码，打到候选出现即可停手。

---

## 一、名义

### 1.1 应物

> 承明心意以相应万物，而为变化。

「应物」二字出于此意。对一套键入方案而言，它指的是：键入的过程应当顺着写的人心里的那个字走，而不是让人去迁就工具的规则。汉字是音、形、义的结合体；一套与它相应的键入方式，所要求的也应当是关于这个字本身的认识——它怎么读、它怎么构成——而不是另一套专为机器设定的符号。

### 1.2 衡码

方案原名「应物音形衡码输入法」。「衡」取权衡之义：音与形在一枚编码里各据其位，不以一方压倒另一方。全拼承担读音，结构与部件承担字形，二者按固定次序前后拼接，分明而不相掩。

衡码有独立的实现（「应物输入法」），是本方案的前身。它用「结构码＋部首码」消歧，与本方案的分歧只在后半段：部首码要求使用者先知道**哪个部件才是部首**、并且知道那个部首的通称——`礻` 要知道叫「示」且不能与 `衤`（衣）相混，认错部首就打不出字。本方案改为「任意一到三个部件、顺序不限、允许多名」（§4.4），结构码照收。两套实现可以并存安装。

### 1.3 足下

实现本方案的 Windows 软件名为「应物足下输入法」，取「千里之行，始于足下」之意。方案是方案，软件是软件：本文只讲方案；软件的架构与使用见仓库的 [README](../README.md)。

### 1.4 作者与状态

本方案与其实现均出自一人之手，目前仍是**草案**：编码规则已定案并有实测，部件命名表已覆盖全部部件但待人工复核，软件可安装可打字但自动化测试未覆盖全部层次。本文凡属未经验证的判断，均在正文中标明。

## 二、缘起

### 2.1 其一：键入的准确性，是对思绪的保护

写作时真正稀缺的不是时间，是思绪的连续。一个念头从成形到落在纸上，中间任何一次停顿都可能让它散掉。键入是这条链上最末、也最频繁的一环——一篇三千字的文章要按下近万次键。这一环上的每一次迟疑、每一次回头修改，都是对上游那个念头的打断。

因此，一套键入方案的首要指标不应是峰值速度，而是**一次把字打对的比例**。

**拼音输入法在这一点上有结构性的困难。**

汉语单字同音极为严重。按本方案的字表实测：只给全拼、不给任何字形信息时，首选命中率为 56.79%，同一串拼音平均对应 38.12 个候选字。也就是说，近一半的字要靠目视候选列表来定。

现代拼音输入法用语言模型把这个数字压下去——按词、按句、按使用历史去猜——但这引入了另一个问题：**候选的顺序由使用者看不见的模型决定**。同一串拼音今天出这个、明天出那个；打错了，使用者既不知道为什么错，也无法保证下一次不错。判断权被交给了不可见的统计。

**在当下以拼音为基础的教育语境里，这个困难还被放大了一层。**

汉语拼音是识字的脚手架，人人会写，于是拼音输入法几乎不需要学。代价是：使用者关于汉字**字形**的那一半知识——这个字是左右还是上下、它由哪些部件组成——在键入时完全闲置。一个人可能认得三千字的写法，但在键盘上这三千字的形他一个也用不上。键入与认字之间的那道联系，被切断了。

**五笔输入法走的是另一端，它的困难在入口。**

五笔只认字形、不认读音，因此不受同音之困，熟练者的速度上限很高。但它要求使用者先学会一套**专为输入而设**的知识：字根如何分区、如何落在键位上、末笔交叉识别码如何补足。这套知识在输入法之外没有用处，学了只能用来打字；而它的记忆量足以让多数人在入门阶段就停下。此外，只认形也意味着一旦遇到不会拆的字，使用者没有第二条路——读音这条他本来就有的路被关掉了。

本方案试图不走这两端中的任何一端：音与形都用，但用的是使用者在学写汉字时就已经具备的知识，不另造一套。

### 2.2 其二：文字的输入方式，是否参与思维的进路

这是一个尚无定论的问题。本方案不假装有答案，只把它摆出来，并说明自己按哪一边下注。

拼音键入的过程大致是：

```text
意  →  音  →  拼音串  →  候选列表  →  视觉检索  →  确认
```

中间多出一步**视觉检索**：候选列表要读一遍、比一遍。这一步调用的是视觉与比对，与正在进行的写作并不同路；它每发生一次，就是一次短暂的切轨。

音形并取的键入过程是：

```text
意  →  字（音与形）  →  码
```

它要求的是对那个字本身的认识。当码足够长、候选足够少时，视觉检索这一步被压缩，甚至不再发生。

这个差别是可以度量的。同一份字表，按使用频次加权：

| 打到哪一级 | 平均候选数 |
|---|---:|
| 只给全拼 | 38.12 |
| 加结构码 | 12.58 |
| 加一个部件 | 4.79 |
| 加两个部件 | 2.00 |
| 加三个部件 | 1.46 |

从 38 到 1.46，是二十余倍的检索量差别。

**但必须如实说明：这个差别不是零。** 实测中约四分之一的字，无论怎么打都不唯一，仍要选一次字（§5.4）。「完全不看候选」做不到，本方案不作此承诺。

那么，**汉字如何键入才是更好的**？本方案的回答是：**让键入所依赖的知识，与汉字本身的构成相一致。** 汉字是音形义的结合体。只取音，是把它当作拼音的转写；只取形，是把它当作图形。音与形并取、次序分明，才与这个字本来的样子相对应——这也正是「应物」二字的意思。

### 2.3 其三：规则应当可被完整理解，而规则所需的知识应当是使用者已有的

输入法是日常工具里被调用得最频繁的一个，一天数千次。正因为频繁，它的行为是否**可预测**就不只是方便问题，而决定了使用者与工具之间的关系。

这里有两件事，应当分开要求。

**第一件：规则本身可被完整理解。**

本方案的编码是确定的：同一串码永远给出同一组候选，顺序只由字频决定，不受使用历史、不受上下文、不受任何不可见模型影响。由此得到一个具体的性质——**打错了，使用者能自己看出错在哪一位**。第三位是结构，第四、五位是部件；候选不对，是结构判错了，还是部件的名字记成了别的，一眼能定位，下一次自己能改对。在候选顺序由模型决定的方案里，「候选不对」是一件没有原因可查的事，使用者只能重试。

这条性质也划出了本方案的一条边界：**不做通用的模糊纠偏**。容错应当做在规则层（例如把方言里常见的音混同登记为等价输入），不做在算法层。算法一旦开始猜使用者想打什么，「能自己看出错在哪一位」就不再成立。

**第二件：规则所需的知识，应当是使用者已经拥有的。**

本方案只用三样东西：

| 要素 | 来源 |
|---|---|
| 读音 | 汉语拼音，识字教育的起点，人人已会 |
| 整字结构 | 左右、上下、包围、品字、独体，规范汉字教学的基本内容 |
| 部件名称 | 三点水、言字旁、宝盖头、提手旁，语文课上就是以「这个部件叫什么」的形式教的 |

这三样都不是为输入法新造的。本方案不要求使用者记住任何一张专用的字根表或键位图；它要求的，是把已经学过的东西用起来。

与 §2.1 的两端对照看最清楚：拼音输入法只用了其中第一样，另两样闲置；五笔三样都不用，而要求另学一套；本方案三样都用，且都是现成的。

**代价要说清。** 「现成」不等于「不用想」。结构大体上看一眼就知道，确实不用学；部件名称则参差——「三点水」人人会说，一个生僻部件叫什么，使用者未必有现成的叫法。本方案为此设了放宽规则（§4.4）：任意一到三个部件皆可、顺序不限、一个部件允许多个名称。这些放宽是承认现实，不是含糊。

## 三、设计思路与原则

### 3.1 音形并取，次序固定

一枚编码分三段，次序不可换：全拼在前，结构居中，部件在后。固定次序换来的是可读性——看到 `qingzsq`，使用者能把它切回「qing / z / s+q」，知道每一位在说什么。混合次序会让码变成不可解读的字符串，失去可自查这一关键性质。

### 3.2 逐级加码，打到够用为止

三段不必打满。`qing`、`qingz`、`qingzs`、`qingzsq` 都是有效编码，候选出现就可以停。常用字往往在第一、二级就已首选命中，生僻字才需要打到满码。**编码长度随需要而变，不是定长。**

这一点与五笔的定长码有根本区别：五笔四码不够则补识别码，本方案的「满码」只是「候选足够少」，没有强制长度。

### 3.3 放宽到「猜得到就能打」

一个没人猜得到的码等于不存在。因此：三部件以上的字不规定该用哪几个；部件的先后不论；一个部件允许有多个名称（通称与本音皆可）。宁可一个字多出几条编码，也不要使用者卡在「这个部件到底该叫什么」上。

这一条的代价是编码行数增加（§5.1），收益是不会把人挡在门外。

### 3.4 规则确定，不猜使用者的意图

同一串码永远给出同一组候选。排序只看字频，不看上下文、不看使用历史。使用者的选择会被记住（§3.7），但记住的方式也是确定的、可查的。

### 3.5 判定以国家标准为据，不以程序推断为据

独体字的判定以《GF 0013—2009 现代常用字部件及部件名称规范》的独体字表为准。此前版本从拆字数据机械推断，而拆字数据对独体字给出的是**笔画树**，于是「山」被推成包围、「口」被推成上下、「月」被推成包围——与任何人的直觉都不符。改为查表后，山、口、月、木、田、一、见一律判为独体。程序推断只用于标准表以外的字。

### 3.6 一切指标可复现

本文、README 与仓库文档中的每一个数字，都能用仓库里的脚本重新算出来（§5.8）。数据改了，数字就该跟着改，不手抄。

### 3.7 使用者的数据留在本机

键入过程中产生的个性化数据（选过哪个候选）只写在本机的用户目录下，纯文本，使用者随时可以打开查看，删掉即等于忘掉全部。诊断日志只记事件，不记内容——使用者打了什么字、选了什么候选，一个字都不记。

## 四、编码规则

### 4.1 音：全拼

不带声调的标准汉语拼音，`ü` 写作 `v`。多音字按读音分别成码。

按字频加权平均 2.97 键，是编码成本的主体。单靠全拼，首选命中 56.79%，平均 38.12 个同码候选。

### 4.2 形（一）：结构码

一个字母，描述整字的拆分方式：

| 码 | 结构 | 例 | 字数占比 | 按字频加权 |
|---|---|---|---:|---:|
| `z` | 左右 | 清、请、轻 | 66.39% | 43.69% |
| `s` | 上下 | 字、先、花、安 | 21.83% | 20.86% |
| `b` | 包围、半包围 | 国、武、回、风 | 7.85% | 11.86% |
| `p` | 品字形、交叠，以及兜底 | 森、品、众 | 0.65% | 0.34% |
| `d` | 独体 | 木、田、山、口、月、一、见 | 3.28% | 23.24% |

两列是两种口径：「字数占比」的分母是 8,757 个（字，读音）对，未加权；「按字频加权」是同一批对按字频加权。二者相差最大的是 `d`——独体只占三个百分点的字数，却占近四分之一的**使用**频次，因为最常用的一批字（一、人、口、山、日、月）大半是独体。评估「好不好学」看左列，评估「打起来什么感觉」看右列。

加上结构码后：3.96 键，首选命中 74.75%，平均候选 12.58。

### 4.3 形（二）：部件码

取部件**名称**的拼音首字母——名称，不是读音。这是整套方案的支点。

名称的来源分三层，按优先级从高到低：

1. **人工名称表**：需要人工判断的部件，逐条登记，优先采用。
2. **GF 0014—2009《现代常用字部件及部件名称规范》国标名称**：人工表没有的，并入国标名称（宝盖、草字头、病字框、倒八、私字边……）。并入方式是**追加**，不覆盖人工名称。
3. **部件自身读音**：以上两层都没有的，用部件本身的读音兜底。

```text
清 = 氵 + 青   左右     氵 叫「水」shuǐ → s     青 qīng → q     →  qingzsq
请 = 讠 + 青   左右     讠 叫「言」yán  → y                     →  qingzyq
情 = 忄 + 青   左右     忄 叫「心」xīn  → x                     →  qingzxq
晴 = 日 + 青   左右     日        rì   → r                     →  qingzrq
字 = 宀 + 子   上下     宀 叫「宝盖」bǎo → b    子 zǐ → z       →  zisbz
```

取名称而非读音，带来一条有用的性质：**变体写法与本字同码**。`氵`＝`水`＝s，`讠`＝`言`＝y，`扌`＝`手`＝s。写法变了，名字没变，码就没变。

**没有名称的部件再往里拆一层。** 顶层部件本身一定保留，只是当它没有名称时，允许用它的下一层子部件来打。名称表就是递归的停止条件：表越全，拆得越浅，码表越小而且越可猜。

### 4.4 四条放宽规则

**其一，任意部件皆可，最多三个。** 一个码最多带的部件字母从早期版本的两个放宽到三个：

```text
轻 = 车 + 又 + 工    左右
     车 chē → c     又 yòu → y     工 gōng → g
     qingz 之后  cy  cg  yc  yg  gc  gy  六种皆可
```

**其二，顺序不限。** `qingzsq` 与 `qingzqs` 都是「清」。这是作者定的硬口径。

**其三，一个部件可以有多个名称。**

```text
彳   有人叫「双人旁」(s)，有人读本音 chì (c)     两个码都认
冂   有人叫「同字框」(t)，有人读 jiōng   (j)     两个码都认
```

**其四，部件别名：「这个部件里看得见什么」。**

「鹏」里看得见「月」，使用者打 `pengzy` 就应该出「鹏」——但鹏的一级部件是「朋」与「鸟」，月在第二层。解决办法不是把拆分全部递归，而是逐条人工勾选：子部件在母部件里看得见、有通行叫法、且新字母与母部件原有字母不同，方才收录。

效果：「鹏」可以用看得见的「月」(y) 来打——`pengzy` 的候选里有鹏，满码 `pengzyn`（月＋鸟）唯一；「崩」同理，`bengsy` 首选命中。

### 4.5 逐级加码

| 级 | 平均键长 | 首选命中 | 前三命中 | 平均候选 |
|---|---:|---:|---:|---:|
| 全拼 | 2.97 | 56.79% | 80.65% | 38.12 |
| ＋结构 | 3.96 | 74.75% | 93.18% | 12.58 |
| ＋一个部件 | 5.03 | 88.13% | 98.33% | 4.79 |
| ＋两个部件 | 6.10 | 96.08% | 99.82% | 2.00 |
| ＋三个部件 | 7.31 | **98.04%** | 99.94% | 1.46 |

合计：平均附加键 0.842，总击键 3.81 键／字，打满后仍需动手选字的比例 1.96%。

### 4.6 词的编码

词的编码与单字同构，只是按**列**排：全拼串＋逐位结构串＋逐位部件串。

```text
苏瑶      su yao        ＋  s z    ＋  c(艹) w(王)          →  suyao / suyaosz / suyaoszcw
你好      ni hao        ＋  z z    ＋  r(人) n(女)          →  nihao / nihaozz / nihaozzrn
杨志鹏    yang zhi peng ＋  z s z  ＋  m(木) s(士) p(朋)    →  yangzhipengzszmsp
部首      bu shou       ＋  z d                             →  bushou / bushouzd
```

三档都是有效编码，打到候选出现就停——与单字的逐级加码是同一套规则。

词表没有收的词（人名、生僻搭配）由**列式解码器**兜底：它不查词表，按「列」直接配，因此词表外的人名、专有名词同样可打。解码器的规则见 [docs/列式解码.md](列式解码.md)。

词表收的是雾凇拼音（rime-ice）按词频取的前 12 万词。

### 4.7 结构码是强制的

结构码不能做成可选项。若 `qingz` 既可能表示「左右结构」，又可能表示部件「竹／足／走」，编码就有歧义。生成器留有 `--no-structure` 开关，可生成无结构码的版本用于评估，但两种编码**不可混用**。

### 4.8 实测示例

以下直接查 `data/zuxia.dict.yaml`，按词频排序，括号里是该码的候选总数。


### 5.1 字表与码表规模

| 项目 | 数值 |
|---|---:|
| 字表规模（字，读音）对 | 8,757 |
| 实际出码汉字 | 8,183 |
| 编码行数 | 275,268 |
| 不同的码 | 181,073 |
| 平均每字码数 | 33.64 |
| 词条数 | 119,964 |
| 词的编码行数 | 619,357 |

单字码表 275,268 行 / 4.4 MB；词码 619,357 行 / 18.6 MB。每字多码是设计的结果，不是冗余：它正是四条放宽规则的代价与收益。

### 5.2 部件命名表

8,757 个汉字拆出 **1,586 种一级部件**。

| 状态 | 数量 | 说明 |
|---|---:|---|
| 人工名称 | 329 条 | 高频部首、读音与通称分歧者、无读音的变体 |
| 国标并入 | 480 条 | GF 0014—2009 名称，追加在人工名称之后 |
| 部件别名 | 210 条 | 「这个部件里看得见什么」 |
| 按自身读音取码 | 兜底 | 以上三层都没有时使用 |

并入国标**之前**：1,586 种顶层部件里 1,261 种没有名称；2,365 字（28.90% 字数 / 34.46% 字频）整个字一个可猜部件都没有。并入国标**之后**：这个数字降到 72 字（0.88% / 4.72%）。拆到底仍然无名的只剩 5 种：疋、亅、匸、夊、羋。

这张表是整个方案的地基，目前**已覆盖全部部件但待人工复核**。

### 5.3 有无结构码的对照

| 版本 | 满码键长 | 打满时首选命中 | 仍需选字 | 平均附加键 | 总击键／字 |
|---|---:|---:|---:|---:|---:|
| 全拼＋任意两部件（无结构） | 4.99 | 96.52% | 3.48% | 0.626 | 3.60 |
| **全拼＋结构＋任意两部件** | 5.99 | **98.16%** | **1.84%** | 0.787 | 3.76 |

保留结构码的理由：它大体上不用学（看一眼就知道左右还是上下）；它把同音字提前分开（「见」与「先」同音，`d`／`s` 一键分家）；它与衡码的码位同构，便于迁移。

### 5.4 已知的不足

**「码打满就唯一」是不对的。** 实测：

| 口径 | 数值 |
|---|---:|
| 打满时唯一的码占比 | 85.03% |
| 打满仍不唯一的字 | 2,205 个（字数 26.95%，字频 26.03%） |
| 任何长度都不唯一的字 | 2,169 个（字数 26.51%，字频 24.74%） |

约四分之一的字、近四分之一的使用频次，**无论怎么打都得选一次字**。满码首选命中 98.04% 与这件事并不矛盾——不唯一不等于不排第一，字频高的那个通常排第一。但「唯一」这个词不能再用来为设计取舍背书。

其余已知欠账：

- **部件命名表待人工复核。** 国标并入的 480 条与按自身读音兜底的部件，未经逐条审阅。
- **无反查。** 想不起某个字的结构位或部件名时，目前没有出路。
- **部件别名不全。** 「出」在一般人眼里是两个「山」，而现行编码只认 `c`（屮）与 `q`（凵）。
- **5 个无名部件**：疋、亅、匸、夊、羋，拆到底仍无通行叫法。

### 5.5 与其他方案的对比

| 方案 | 依赖知识 | 入门难度 | 满码首选 | 可自查错误 |
|---|---|---|---:|---|
| 纯拼音 | 拼音 | 极低 | 56.79% | 否（模型决定） |
| 音形（本方案） | 拼音＋结构＋部件名称 | 低 | 98.04% | 是 |
| 五笔 | 专用字根表＋键位图 | 高 | 极高 | 是 |

三套方案各有取舍，不存在绝对的优劣。本方案的立足点是：在入门代价可控的前提下，尽量提高一次命中率，并保持规则的可自查性。

### 5.6 取舍说明

0.3.0 之后的版本是明确的取舍，不是纯改进：

- 一级和二级部件码的首选率退了（89.78%→88.13%，98.16%→96.08%）
- 平均同码候选变多（4.16→4.79，1.43→2.00）
- 总击键从 3.76 涨到 3.81（+1.3%）

换来的是打满唯一性从 82.45% 升到 85.03%，以及更多拆法有码可打。**这是一次明确的取舍，不是纯改进。**
