# 列式解码：不靠词库也能打出任何词

## 为什么需要它

足下的词组码是三段拼接，逐位左对齐：

```
全拼串        逐位结构串    逐位部件串
suyao    +    sz       +    cw        =  苏瑶
```

| 字 | 拼音 | 结构 | 部件 | 部件字母 |
|---|---|---|---|---|
| 苏 | su | 上下 `s` | 艹 办 | `c` / `b` |
| 瑶 | yao | 左右 `z` | 王 䍃 | `w` / `y` |

规则与单字完全同构：一个字时退化成 `su` + `s` + `c`，正是现有的单字码。
打字的人只有一套规则要记，也不需要判断「这个词里哪个字重了」。

代价是 Rime 自带的 `table_translator` 切不动这种码。它按「行」切分——一个
词条一条码；而这里的结构位、部件位跟它们描述的那个字**并不相邻**，得按
「列」去配。所以解码器必须自己写。

`data-tools/decode_zuxia.py` 是这个解码器的原型，`src/Decoder.cpp` 是随 DLL 出货的
C++ 版（0.4.0 起），两边逐条对应，各有自检。

## 算法

1. **切音节。** 从头做 DP，把前缀切成若干个合法拼音音节（音节表 414 个，
   封闭集）。一串码可能有多种切法（`suyaoszcw` 也能读成 `su+ya+o`），全部
   保留，最后合并候选。
2. **分派尾巴。** 设切出 n 个音节，剩下的尾巴长度必须 ≤ 3n，否则这串码不
   可能是 n 个字。尾巴按列分派：第 `i` 位是第 i 个字的结构，第 `n+i` 位是
   它的第一个部件，第 `2n+i` 位是第二个部件。左对齐、可以只填一半。
3. **逐位查表。** 每个位置拿 (拼音, 结构, 部件…) 去查单字索引，得到这一位
   还站得住的字。
4. **定向搜索。** 从左到右扩展，每步只留分数最高的 400 个前缀。分数 =
   Σ log(字频) + Σ log(相邻二元组频次)。词库命中的组合直接置顶。

第 4 步的二元组是关键。只按字频排，「杨志鹏」会输给「样直鹏」——每个字单
看都更常见，连起来却没人这么写。二元组从同一份词库统计，161,558 条，不需
要额外语料。

## 实测

样本：rime-ice `base.dict.yaml` 词频前 2 万条，按词频加权。
「纯拼」一栏用**留一法**——解码前把这个词自己对二元组的贡献扣掉，模拟词库
里根本没有它。覆盖率 100%，没有跳过的词条。0.4.2 码表重测（`--bench`）；
速度是 Python 原型在开发机上的数。

| 打法 | 首选 | 前三 | 速度 |
|---|---:|---:|---:|
| 纯拼（词库里没有），每字 1 个部件 | 96.63% | 99.43% | 0.31 ms |
| 纯拼（词库里没有），每字 2 个部件 | **99.06%** | 99.93% | 0.06 ms |

## 三条补位规则

列必须对齐，否则第 `i` 位说的是哪个字就讲不清。三种字要补：

- **只有一个部件的字**（216 个）：第二轮把第一个部件再写一遍。
- **拆不出部件的字**（32 个：入 心 舟 女 人 手 …）：部件位写自己读音的
  首字母，`入` = `ru` + `d` + `r`。
- **独体字**（259 个，0.4.2 起）：还可以把整个字当作唯一的部件，部件位写
  自己读音的首字母，第二轮照抄：`月` = `yue` + `d` + `y`，于是 `揽月` =
  `lanyuezdly`。这是另一种拆法，不和笔画碎片（月 的 冂、二）混搭。单字码
  表同一版跟上（方案文档 §4.4 其五）。

三条都是机械规则，不需要打字的人做任何判断。

## 和 Rime 共用一页：补位与带头

解码器不单独出窗口，它的候选和 Rime 的候选排在同一页（`src/RimeEngine.cpp`
的 `FillDecodedCandidates`）：

- **补位**（默认）：Rime 的候选原样在前，解码器填这一页剩下的空位。纯拼音
  （`woxiangwen`）永远是补位，Rime 的首选一个字不动。
- **带头**（0.4.2 起）：码已经进了结构／部件列，而 Rime 的首选**不合列**——
  没有哪种切法能让它的每个字落在自己那一列上（`Decoder::Fits`）——解码结果
  排到最前，这一页给 Rime 留最多三位。`lanyuezd` 被 Rime 读成「蓝＋刖」、
  占满一页，就是靠这条修好的。

两边混排之后，数字键、空格、上下键按「这个位置上是谁」处理（`slots_`），
不会出现「按 3 选到第 4 个」。

## 这对词组表意味着什么

词组表（现在 619,357 行、18.6 MB）只剩**排序先验**的作用，不再是「能不能
打出来」的前提。可以大幅瘦身，甚至换成更紧凑的二元组表（161,558 条，约
2 MiB）。C++ 版 0.4.0 起已随 DLL 出货，这一步等真机验过再定，还没做。

## 命令

```
python3 data-tools/decode_zuxia.py suyaoszcw          # 解一个码
python3 data-tools/decode_zuxia.py suyaoszcw --no-prior   # 不看词库
python3 data-tools/decode_zuxia.py --selftest         # 15 条固定用例
python3 data-tools/decode_zuxia.py --bench            # 2 万词基准（约 20 秒）
```
