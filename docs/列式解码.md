# 列式解码：不靠词库也能打出任何词

## 为什么需要它

足下的词组码是三段拼接，逐位左对齐：

```
全拼串        逐位结构串    逐位部件串
suyao    +    sz       +    cw        =  苏瑶
```

| 字 | 拼音 | 结构 | 部件 | 部件字母 |
|---|---|---|---|---|
| 苏 | su | 上下 `s` | 艹 办 | `c` / `b` |
| 瑶 | yao | 左右 `z` | 王 䍃 | `w` / `y` |

规则与单字完全同构：一个字时退化成 `su` + `s` + `c`，正是现有的单字码。
打字的人只有一套规则要记，也不需要判断「这个词里哪个字重了」。

代价是 Rime 自带的 `table_translator` 切不动这种码。它按「行」切分——一个
词条一条码；而这里的结构位、部件位跟它们描述的那个字**并不相邻**，得按
「列」去配。所以解码器必须自己写。

`data-tools/decode_zuxia.py` 就是这个解码器的原型。

## 算法

1. **切音节。** 从头做 DP，把前缀切成若干个合法拼音音节（音节表 414 个，
   封闭集）。一串码可能有多种切法（`suyaoszcw` 也能读成 `su+ya+o`），全部
   保留，最后合并候选。
2. **分派尾巴。** 设切出 n 个音节，剩下的尾巴长度必须 ≤ 3n，否则这串码不
   可能是 n 个字。尾巴按列分派：第 `i` 位是第 i 个字的结构，第 `n+i` 位是
   它的第一个部件，第 `2n+i` 位是第二个部件。左对齐、可以只填一半。
3. **逐位查表。** 每个位置拿 (拼音, 结构, 部件…) 去查单字索引，得到这一位
   还站得住的字。
4. **定向搜索。** 从左到右扩展，每步只留分数最高的 400 个前缀。分数 =
   Σ log(字频) + Σ log(相邻二元组频次)。词库命中的组合直接置顶。

第 4 步的二元组是关键。只按字频排，「杨志鹏」会输给「样直鹏」——每个字单
看都更常见，连起来却没人这么写。二元组从同一份词库统计，161,558 条，不需
要额外语料。

## 实测

样本：rime-ice `base.dict.yaml` 词频前 2 万条，按词频加权。
「纯拼」一栏用**留一法**——解码前把这个词自己对二元组的贡献扣掉，模拟词库
里根本没有它。覆盖率 100%，没有跳过的词条。

## 两条补位规则

列必须对齐，否则第 `i` 位说的是哪个字就讲不清。两种字会让列缺口：

- **只有一个部件的字**（223 个）：第二轮把第一个部件再写一遍。
- **拆不出部件的字**（32 个：入 心 舟 女 人 手 …）：部件位写自己名字的
  首字母，`入` = `ru` + `p` + `r`。

两条都是机械规则，不需要打字的人做任何判断。

## 这对词组表意味着什么

原定的 867,839 行词组表（约 21.5 MiB）现在只剩**排序先验**的作用，不再是
「能不能打出来」的前提。可以大幅瘦身，甚至换成更紧凑的二元组表（161,558
条，约 2 MiB）。这一步等 C++ 版落地、真机验过再定，本轮不动。

## 移植进 C++ 的清单

- [ ] 单字索引：`(拼音, 结构, 部件…) -> 字集`，从 `data/zuxia.dict.yaml`
      构建，或预生成成二进制随安装包发。
- [ ] 音节表 414 条，钉死在代码里。
- [ ] 二元组表 161,558 条，作为数据文件发。
- [ ] 定向搜索宽度 400，与原型一致。
- [ ] `decode_zuxia.py --selftest` 的 11 条用例照搬成 C++ 断言，进
      `tools/engine-test.cpp`。

## 命令

```
python3 data-tools/decode_zuxia.py suyaoszcw          # 解一个码
python3 data-tools/decode_zuxia.py suyaoszcw --no-prior   # 不看词库
python3 data-tools/decode_zuxia.py --selftest         # 11 条固定用例
python3 data-tools/decode_zuxia.py --bench            # 2 万词基准
```
